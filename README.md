# 대신고 석식봇 v2 — 공기계 없이 돌리는 급식 조회 웹사이트

## 무엇을 만들었나요?

- 공개된 `https://orya.ng/api/meals` 의 **텍스트 JSON**을 정해진 시간에 조회합니다.
- 오늘부터 다음 열흘 정도의 날짜를 확인하고 석식을 `docs/data/meals.json`으로 정리합니다.
- `docs/index.html`이 GitHub Pages에서 메뉴 조회 화면과 `!석식`, `!내일석식`, `!이번주석식`, `!11월2일석식`, `!2026-11-02석식`, `!중식` 명령어 미리보기를 제공합니다.
- 학교 홈페이지 이미지를 읽는 AI는 필요하지 않습니다.
- 로그인 정보, 쿠키, 비밀번호를 코드에 넣지 않습니다.

## 주의 — 현재 확인된 사실과 미확인 사항

1. 사용자의 **시크릿 브라우저**에서 `https://orya.ng/api/meals?date=10%2F28` JSON 응답 확인됨.
2. **GitHub Actions 클라우드 환경**에서 접근 가능한지는 아직 미검증입니다. `403`, `429`, 자동화 이용 제한이 있을 수 있습니다.
3. `dinnerSource: "mcp"`는 문자열 식별자이며, **Model Context Protocol 사용 여부를 입증하지 않습니다.** 오량인 서버의 내부 데이터 수집 방식은 알 수 없습니다.
4. 석식 필드가 없으면 **등록 전/미제공**을 의미하며 석식 운영 여부는 모릅니다.
5. 오량인은 타인이 운영하는 서비스입니다. 공개 조회는 된다고 해도 타 프로젝트에서 주기적으로 자동 수집해도 된다는 허락을 뜻하지 않습니다. 이용 조건을 지키고 요청 간격을 유지하세요. 제한되면 수집을 중단하고 공식 제공/허용 방식을 확인해야 합니다.
6. 이 웹앱은 **카카오톡 일반 단톡방 자동응답 기능을 구현한 것은 아닙니다.** 카카오 단톡방에 자신이 만든 봇을 공식 등록하는 공개 API는 확인되지 않았습니다.

## 가장 쉬운 실행 방법 — 내 컴퓨터에서

압축을 풀고 프로젝트 폴더에서 Python 3.10 이상을 사용합니다.

```powershell
python scripts/collect.py
python -m http.server 8000 --directory docs
```

그다음 `http://localhost:8000`을 방문합니다. 첫 번째 명령이 실패하면 네트워크 제약 때문에 `meals.json`이 비어 있을 수 있습니다. 비밀번호/쿠키를 넣어 해결하려고 하지 마세요.

## 휴대폰/컴퓨터를 24시간 켜두지 않는 배포

1. GitHub에서 **공개(Public) 저장소** `dshs-mealbot`을 새로 만듭니다.
2. 이 프로젝트의 압축을 풀고, **`.github` 폴더를 포함한 파일들**을 저장소 최상위에 업로드합니다. (폴더 안에 한 단계 더 넣지 말 것)
3. GitHub 저장소의 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택합니다.
4. **Actions**에서 `Refresh meals and deploy Pages` 워크플로가 나타나면 `Run workflow`를 눌러 실행합니다. 첫 업로드 시 `push`로도 자동 실행됩니다.
5. **Actions → 실행 내역**에서 `Refresh public meal data`가 성공했는지 확인합니다.
6. Pages에 표시된 URL (일반적으로 `https://사용자명.github.io/dshs-mealbot/`)을 열어 데이터를 확인합니다.

GitHub Actions는 한국 시간 기준 **06:27, 16:27**에 예약 실행하도록 설정돼 있지만 정확한 시각은 보장되지 않습니다. 스케줄 작업은 저장소 비활성화 및 GitHub 정책에 따라 중단될 수 있습니다.

이 작업은 데이터를 매번 다시 조회해서 즉시 Pages에 게시하므로 별도의 `git push` 권한이 필요 없습니다. `docs/data/meals.json`은 다음 실행마다 새로 만들어 배포하며 누적 DB는 아닙니다.

> 최초 저장소 업로드 후 Pages가 비어 있다면: Actions 실패 로그를 확인하세요. 클라우드 환경에서 오량인 API가 차단된 경우, 이 방식은 그대로 작동하지 않을 수 있습니다.

## 데이터 처리 설계

- `GET /api/meals`에서 이번 주 데이터가 나오면 먼저 사용합니다.
- 누락된 날짜만 `GET /api/meals?date=M/D`로 추가 조회합니다. 최대 10건/1회, 0.8초 간격으로 요청합니다.
- `isoDate`가 실제 요청 날짜와 다르면 폐기합니다 (연도 혼동 방지).
- 석식이 없으면 `null`로 보관합니다. **휴무라고 판단하지 않습니다.**
- 오늘 기준 주변 날짜를 빠르게 조회하는 **단기 조회 캐시**입니다. 다음 달 전체 식단이 미리 제공된다는 보장은 없습니다.
- 웹페이지는 JSON 메뉴를 안전하게 `textContent`로 표시합니다.
